# 校园暖廊通 CampusLink

> 冬季校园**室内暖廊**智能导航 Web 应用 —— Vue 3 + Vite 课程作业项目
>
> ⚠️ 当前为 **模拟数据演示版**：地图上的建筑位置、名称与暖廊连接均为课程作业虚构数据，
> **不代表任何真实校园（包括任何真实高校）的实际布局**。拿到真实地图后按本文第 5 节替换即可。

---

## 1. 它能做什么

| 功能 | 说明 |
|---|---|
| 校园地图 | 纯 SVG 手绘模拟校园底图，标注教学楼、图书馆、宿舍、食堂、体育馆、校门等 13 个地点 |
| 起终点选择 | 下拉框选择，也支持"地图点选"模式和一键交换起终点 |
| 路线规划 | 本地 Dijkstra 算法，可选择「暖廊优先 / 均衡 / 最短距离」三种偏好 |
| 室内优先 | 给室外路段乘一个"冬季体感系数"（暖廊优先模式下 1 米室外 = 5 米），因此路线会**绕行暖廊**以减少露天步行 |
| 路线详情 | 总距离、预计步行时间、**室内里程占比**、逐段室内/室外标注、途经建筑 |
| 建筑搜索 | 支持中文名、英文名、拼音别名模糊搜索 |
| 建筑信息 | 楼层、开放时间、规模、简介、设施标签，可一键设为起点/终点 |
| **双模式切换** | 顶栏「模拟校园 / 真实校园」一键切换，两套数据互不覆盖 |
| **真实校园拓扑** | 19 栋建筑 / 11 个楼层节点 / 6 条暖廊 / 18 条候选；**示意布局、不算距离** |
| **真实方位示意地图** | 15 栋楼人工标定（14 已标定 + 1 存疑）+ 缩放拖动 + 暖廊示意线；**非测绘精度**，未标定建筑不上图 |
| **真实模式路线查询** | 只选建筑即可查询：BFS 找官方暖廊段数最少的路线，拓扑图高亮；楼内换乘标为建模假设；**不计算距离与步行时间** |

## 2. 快速开始（三条命令）

> 需要先装好 **Node.js 18 或更高版本**（命令行里输入 `node -v` 能显示版本号即可）。

```powershell
# 1) 进入项目目录
cd D:\JXAU_sy\A哈工大\DSH\CampusLink

# 2) 第一次运行时安装依赖（只需一次，会下载几十 MB，需要联网）
npm install

# 3) 启动开发服务器
npm run dev
```

启动成功后，终端会显示类似：

```
  VITE v6.x  ready in 400 ms
  ➜  Local:   http://localhost:5173/
```

用浏览器打开 `http://localhost:5173/` 就能看到页面。

**如果 `npm run dev` 报错 `spawn EPERM`：**
这是 Vite 在加载配置文件时调用子进程被系统/沙箱拦截导致的（常见于 AI 编程工作区、
学校管控电脑、部分杀毒软件）。换成这个命令即可，功能完全一样：

```powershell
npm run dev:compat
```

**打包发布：**

```powershell
npm run build     # 产物输出到 dist/ 目录
npm run preview   # 本地预览打包结果
```

（同样地，如果 `npm run build` 报 `spawn EPERM`，用 `npm run build:compat`。）

**算法自检（不看浏览器也能验证路线）：**

```powershell
npm run check
```

它会打印 6 组典型起终点在三种偏好下的距离、室内外里程和经过的暖廊。

**停止开发服务器：** 在运行的终端窗口按 `Ctrl + C`。

> 💡 如果 `npm install` 很慢，可以临时换成国内镜像：
> `npm config set registry https://registry.npmmirror.com`

## 4. 路线算法是怎么工作的

一句话：**把校园当成一张"图"，然后找"体感最省"的那条路。**

1. **建图**
   - 每栋建筑是一个「节点」，每个暖廊交叉口（`JUNCTIONS`）也是节点。
   - 每条暖廊 / 室外步道是一条「边」，双向可走。
   - 边长不用手写，由两端坐标自动计算：`米数 = 折线长度 × 0.5`（比例尺 1 地图单位 = 0.5 米）。

2. **加权**（这是"室内优先"的关键）

   | 偏好 | 室内成本 | 室外成本 |
   |---|---|---|
   | 暖廊优先 | 1 米 = 1 | 1 米 = **5** |
   | 均衡 | 1 米 = 1 | 1 米 = 2.5 |
   | 最短距离 | 1 米 = 1 | 1 米 = 1 |

   室外加权后，"绕暖廊多走 100 米"可能比"露天少走 50 米"更划算，
   于是算法会主动选择室内路线 —— 这就是「减少冬季室外步行」的实现方式。

3. **Dijkstra 最短路**
   在加权图上从起点出发，每次选出"当前累计成本最小"的节点扩展，直到到达终点，
   再沿记录的"上一跳"倒推出完整路线。节点只有十几个，用线性扫描找最小值即可，代码更直观。

> 复杂度：节点数 V ≈ 15、边数 E ≈ 20，每次规划都是毫秒级。

## 5. 换成真实校园地图（后续要做的事）

只需要动 **两个数据文件**，界面和算法都不用改：

1. **`src/data/buildings.js`**
   - 修改每栋楼的 `x`、`y`（中心点坐标）、`w`、`h`（宽高），坐标系是 SVG 的 `1000 × 660`；
   - 修改名称、楼层、开放时间、简介、`aliases`（搜索别名）。
   - 如果真实校园比例尺不同，改 `CAMPUS_META.scaleMetersPerUnit`（现在是 0.5 米/单位）。

2. **`src/data/corridors.js`**
   - 按真实暖廊连接关系增删 `from` / `to`；
   - `type` 填 `'indoor'`（暖廊内）或 `'outdoor'`（露天）；
   - 走廊不是直线时，用 `via: [{ x, y }]` 加拐点。

3. 如果需要真实底图图片，可在 `CampusMap.vue` 的 `<svg>` 最底层插入
   `<image href="/campus.png" x="0" y="0" width="1000" height="660" />`，
   再按同一坐标系摆放建筑方块。

> 注意：替换真实地图时请确认你有权使用该地图素材。

### 5.1 真实暖廊数据的采集规则（哈工大一校区）

`src/data/realCampus/` 是为真实校园单独准备的数据目录，**与上面的模拟数据互不影响**，
也还没有接入 `routePlanner.js`——所以现有地图和路线规划照常工作。

| 文件 | 作用 | 当前状态 |
|---|---|---|
| `rules.js` | 规则、枚举、工厂函数、跨表校验 | ✅ 已完成 |
| `buildings.js` | 真实建筑表 | ✅ 19 栋 |
| `nodes.js` | 楼层级节点表（暖廊端点） | ✅ 11 个 |
| `corridors.js` | 已确认暖廊（可导航） | ✅ 6 条 |
| `candidates.js` | 候选暖廊（**不参与导航**） | ⬜ 18 条待核实 |
| `dataset.js` | 统一出口，加载时自动校验 | ✅ 已完成 |
| `README.md` | 数据模型说明、校验清单 | ✅ 已完成 |

三条硬规矩：

1. 建筑名称、暖廊编号、连接楼层**只能来自官方地图** <https://map.hit.edu.cn/2d/>；
2. 距离未知一律 `null`，禁止估算，也禁止用直线距离冒充；
3. 官方地图已标注的暖廊，统一按 `bidirectional: true` 建模，`access_status` 记为
   `assumed_open`（假设可通行）—— 这是**项目假设**，不是核实结论。

因此网页顶部固定显示这句提示（常量见 `rules.js` 的 `DISCLAIMER`）：

> 本系统为课程演示作品，暖廊通行状态基于建模假设，实际以学校公告为准。

**端点用楼层级节点，不用建筑**：X6 号暖廊两端都在 A10公寓（东侧2层 / 西侧3层），
若端点还是建筑 ID 就会被误判成自环。所以暖廊连接的是
`节点 = 建筑 + 楼层 + 方位`，同一栋楼的不同节点可以相连，节点自环才禁止。

数据改完跑一次自检（19 项校验：节点引用 / 编号重复 / 楼层 / 同建筑连接）：

```powershell
npm run check:data
```

真实模式的 BFS 路线查询另有一套测试（16 项：直连 / 多段 / 同建筑节点 / 未连通）：

```powershell
npm run check:real-route
```

**数据为空不是遗漏**：在拿到官方名称与连接关系之前，任何先填进去的记录都属于编造，
所以两个数组刻意留空，并用 `createBuilding()` / `createCorridor()` 的校验器拦住不合规数据。

## 6. 常见问题

**Q：`npm install` 报错 EPERM / 权限不足？**
A：多出现在公司或学校电脑的杀毒软件拦截。把项目放到用户目录下，或用管理员权限的终端重试。

**Q：`npm run dev` 报 `spawn EPERM`？**
A：Vite 加载配置文件时需要一个子进程，被系统或沙箱拦截时就会报这个错。
直接改用 `npm run dev:compat`（打包用 `npm run build:compat`），功能完全一致。

**Q：端口 5173 被占用？**
A：Vite 会自动顺延到 5174、5175…… 看终端提示的地址即可；也可以改 `vite.config.js` 里的 `server.port`。

**Q：页面一片空白？**
A：按 `F12` 打开浏览器控制台看红色报错；最常见原因是依赖没装好，重新执行 `npm install`。

**Q：为什么没有用高德 / 百度地图 API？**
A：本项目第一版按要求**不接入付费 API**，路线规划完全在本地完成（Dijkstra），
这样既能离线演示，也便于课程讲解算法本身。后续如需真实路网，可把 `corridors.js` 换成
地图服务返回的步行路网数据，算法层几乎不用改。
